# Licensing and redistribution audit

**Status:** ADR-ready research recommendation for [Audit licensing and redistribution constraints](https://github.com/Sheape/pi-sandwich/issues/21)  
**Evidence date:** 2026-07-26  
**Scope:** exact upstream versions named below and exact direct dependencies currently locked in this repository. Transitive dependencies are out of scope except where an audited published artifact already bundles their code or notices.

> **Not legal advice.** This is an engineering inventory of primary-source license text and package metadata. Copyrightability, derivative-work status, trademark use, generated-output rights, and sufficiency of notices depend on facts and jurisdiction. Counsel must decide ambiguous cases identified below.

## Answer

The audited top-level components and direct packages declare MIT or Apache-2.0; exact Vite+ artifacts additionally bundle permissively licensed Apache-2.0, BSD-2-Clause, BlueOak-1.0.0, CC0-1.0, ISC, and MIT code. No copyleft incompatibility was found for the intended independent npm packages. That conclusion does **not** make copying notice-free. MIT copies or substantial portions must retain copyright and permission text; Apache-2.0 distributions must satisfy section 4, including a license copy, retained notices, prominent modification notices, and any applicable upstream `NOTICE`. Apache-2.0 section 6 and the MIT texts do not grant broad rights to upstream names or logos.

Use boundaries make the practical difference:

- **Runtime/peer integration:** let Pi host the extension; let RTK and Serena remain separately installed processes/tools; let Pi own provider SDKs. A package name, version constraint, protocol call, or command invocation does not itself place upstream source in the pi-sandwich tarball.
- **Linked dependency:** importing and shipping a dependency as an npm dependency is separable from copying it into `dist`, but release archives, containers, standalone binaries, vendored stores, and bundles do redistribute dependency code. Those payloads need their own complete license inventory.
- **Copied source/fixtures:** copied implementation, tests, snapshots, or documentation remain upstream material. Preserve exact provenance and applicable notices; for Apache-2.0 modifications, mark changes. Prefer no copies.
- **Command/output knowledge:** independently describe observed command names, flags, schemas, and behavior in original prose and generate outputs from original tiny repositories. Do not copy upstream prose, fixture repositories, parser code, logos, or large help/error snapshots. Whether a substantial command grammar or output corpus is protectable is counsel-needed ambiguity.

## ADR-ready constraints summary

**Decision:** keep license-bearing upstream code outside pi-sandwich package payloads unless a measured requirement makes redistribution necessary. Core integrates with Pi's public host API; RTK and Serena remain separate optional installations; Vite+ remains dev-only and command-invoked; provider SDK ownership remains inside Pi. Adapters describe protocols/output structures in original code and prose and use original generated fixtures.

**Normative constraints:**

1. **No publication before own-license hygiene.** Add a canonical project license, replace starter package metadata, and prove each npm tarball contains the intended project license.
2. **No accidental bundling.** Published adapters must not bundle Pi, RTK, Vite+, Serena, provider SDKs, TypeScript, release tools, or their fixture trees. CI must inspect packed file lists and bundled dependency inventories.
3. **Dependency classification is explicit.** Every package manifest entry is labeled runtime, optional peer/host, or dev-only. A tool needed only to generate fixtures cannot become a consumer dependency.
4. **Original fixtures by default.** Generate fixtures from project-owned tiny repositories, record `{tool identity, exact version, command, platform, color/CI mode}`, sanitize user/secret/path content, and keep raw provenance outside production packages unless required. Unknown output shapes fail open.
5. **Copies require a ledger.** Any exception records source URL/commit/path, copied/modified status, applicable license, required copyright text, upstream `NOTICE`, destination packages, and removal owner. Apache-derived files carry prominent modification notices. Vite+ composite artifact licenses and TypeScript `NOTICE.txt` travel intact with redistributed payloads.
6. **Command knowledge stays clean-room.** Implement from documented interfaces and independently observed behavior; do not translate upstream parser/source code or prose into near-copy fixtures/specs. Seek counsel before publishing substantial help/error/output corpora or recreating a full command grammar.
7. **Compatibility names are factual, not branding.** Do not use upstream logos, claim official status, or name packages as though sponsored. Search exact-version official trademark policies and obtain counsel before final public names. Apache's trademark clause is restrictive; MIT is silent, not a grant.
8. **Release artifacts trigger a fresh audit.** npm dependencies installed separately, source archives, bundled JS, native binaries, containers, vendored pnpm stores, and single-file executables have different payloads. Generate `THIRD_PARTY_NOTICES` from the actual artifact, not only manifests. Re-audit upgrades and all newly proposed direct dependencies.
9. **Pi packaging anomaly stays visible.** Do not copy its license-less npm tarball into a distribution. If Pi source/artifact must be redistributed, include the canonical MIT notice and obtain upstream/counsel clarification first.
10. **Service terms remain separate.** SDK code licenses do not clear provider API use, data retention, model outputs, or provider marks. Those require a distinct terms/privacy review if architecture expands beyond Pi-local request observation.

**Consequences:** package boundaries remain small and independently publishable; adapters can be optional without importing tool ecosystems; fixture maintenance favors reproducible generation over copied golden files; direct provider coupling and notice load are avoided. Cost: integration tests need separately installed pinned tools, release checks must inspect actual tarballs, and copied-output or branding proposals may pause for counsel.

## Verification method and limits

Primary metadata was read from the exact repository tags/commits and official npm/PyPI version endpoints. Official npm tarballs were unpacked to enumerate root `LICENSE`/`NOTICE` files; the Serena wheel was checked likewise. The repository's manifests and lockfile establish only current direct **development** dependencies. No unrelated transitive dependency audit, patent search, trademark clearance, service-terms review, or legal conclusion was performed.

## One-line gist

> Keep Pi, RTK, Vite+, Serena, and provider SDKs outside published package payloads; use peer/process/protocol boundaries and original fixtures, and block release until package LICENSE/NOTICE verification and counsel clears branding or copied-output ambiguity.
