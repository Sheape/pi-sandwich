# Provider-native compaction through Pi provider paths

_Status: verified against installed Pi `0.82.1`, immutable source tag `v0.82.1` (`b4f293684bba718d59cc1157679bcf6157b3a7f5`), OpenAI Node `6.26.0`, and current first-party provider docs on 2026-07-26._

## Decision summary

**Gist:** Use Pi-managed compaction now; provider-native compaction is real at OpenAI/Anthropic but no stock Pi provider path safely retains its compaction state.

Do not enable native compaction by payload mutation alone. Keep Pi's default compaction as the production path. Reconsider native compaction only after Pi has a typed provider capability and round-trip representation for native compaction blocks/windows, usage, and recovery. A provider adapter may prototype that seam; a sidecar design is deliberately out of scope.

## What is actually implemented

Pi has one built-in compaction mechanism: Pi chooses a cut point, serializes old messages, asks the active model for a Markdown checkpoint, writes a `CompactionEntry`, then rebuilds model context as the summary plus entries from `firstKeptEntryId` onward. Repeated compactions feed the prior summary into the next summary. Full pre-compaction entries remain in session JSONL; only model-visible context is lossy. The persisted entry is `{summary, firstKeptEntryId, tokensBefore, details?, usage?, fromHook?}`—not a provider-native state object ([entry type](https://github.com/earendil-works/pi/blob/b4f293684bba718d59cc1157679bcf6157b3a7f5/packages/coding-agent/src/core/session-manager.ts#L69-L80), [context rebuild](https://github.com/earendil-works/pi/blob/b4f293684bba718d59cc1157679bcf6157b3a7f5/packages/coding-agent/src/core/session-manager.ts#L404-L469), [preparation](https://github.com/earendil-works/pi/blob/b4f293684bba718d59cc1157679bcf6157b3a7f5/packages/coding-agent/src/core/compaction/compaction.ts#L692-L788)). Tool results are truncated to 2,000 characters in summary serialization, so exact older tool output is retained only in JSONL, not model context ([Pi compaction docs](https://github.com/earendil-works/pi/blob/b4f293684bba718d59cc1157679bcf6157b3a7f5/packages/coding-agent/docs/compaction.md#message-serialization)).

Summary calls are standalone, use a fresh routing session ID, and set `cacheRetention: "none"`, intentionally preventing one-off cache writes ([source](https://github.com/earendil-works/pi/blob/b4f293684bba718d59cc1157679bcf6157b3a7f5/packages/coding-agent/src/core/compaction/compaction.ts#L555-L580)). Main-turn cache keys remain session-stable, but compaction changes the exact conversation prefix; Pi treats the next request as a legitimate new prefix rather than a cache miss regression ([source](https://github.com/earendil-works/pi/blob/b4f293684bba718d59cc1157679bcf6157b3a7f5/packages/coding-agent/src/core/cache-stats.ts#L104-L129)).

## Public seams

* `session_before_compact` receives `preparation`, complete branch entries, custom instructions, reason (`manual|threshold|overflow`), retry intent, and an abort signal; it may cancel or return a Pi `CompactionResult`. `session_compact` reports successful persistence ([types](https://github.com/earendil-works/pi/blob/b4f293684bba718d59cc1157679bcf6157b3a7f5/packages/coding-agent/src/core/extensions/types.ts#L585-L607), [result](https://github.com/earendil-works/pi/blob/b4f293684bba718d59cc1157679bcf6157b3a7f5/packages/coding-agent/src/core/extensions/types.ts#L1106-L1109)). This seam accepts a **text summary and Pi cut point**, not an opaque provider window.
* `ctx.compact()` / SDK `session.compact()` trigger Pi-managed compaction. `compaction_start` / `compaction_end` SDK events expose result, abort, retry, and error state ([flow](https://github.com/earendil-works/pi/blob/b4f293684bba718d59cc1157679bcf6157b3a7f5/packages/coding-agent/src/core/agent-session.ts#L1778-L1920)).
* `before_provider_headers` can mutate headers; `before_provider_request` can replace the serialized request; `after_provider_response` exposes only status and headers before stream consumption ([types](https://github.com/earendil-works/pi/blob/b4f293684bba718d59cc1157679bcf6157b3a7f5/packages/coding-agent/src/core/extensions/types.ts#L669-L690)). There is no public raw response-body/output-item hook.
* A complete custom `Provider`/`streamSimple` can own a non-standard protocol, but Pi's `AssistantMessage` and `CompactionEntry` still have no native-compaction block/window type ([custom-provider docs](https://github.com/earendil-works/pi/blob/b4f293684bba718d59cc1157679bcf6157b3a7f5/packages/coding-agent/docs/custom-provider.md#custom-streaming-api)).

## Retention and cache boundaries

### OpenAI native

Server-side stateless chaining must append all output items, including encrypted compaction; callers may drop items before the most recent compaction item. With `previous_response_id`, send only new input and do not prune. Standalone output is the canonical next window and must be replayed as-is; it may contain retained old items plus the opaque compaction item. Both modes can use `store:false`; standalone is stateless/ZDR-friendly ([guide](https://developers.openai.com/api/docs/guides/compaction)). Pi currently cannot serialize that item into session state.

OpenAI prompt caching matches exact prefixes. `prompt_cache_key` influences routing, not semantic reuse; changed compacted prefixes still miss. Cache reads/writes are visible as `cached_tokens` / `cache_write_tokens`; GPT-5.6+ writes are billed and explicit breakpoints are available ([official caching guide](https://developers.openai.com/api/docs/guides/prompt-caching)).

### Anthropic native

The returned `compaction` block contains the generated summary; replaying it makes the API ignore blocks before it. A later compaction supersedes earlier context. Compaction adds a sampling iteration and billing/rate-limit usage; consumers must sum `usage.iterations`. A new summary is a new cache prefix; Anthropic recommends a system-prompt cache breakpoint so the static system remains reusable ([official docs](https://platform.claude.com/docs/en/build-with-claude/compaction#prompt-caching)).

### Pi-managed

Model-visible state is textual summary + recent kept entries. Full history and provider messages remain in JSONL for `/tree`; exact old details are not in the active context. Default details cumulatively retain read/modified file lists. The one-off summary request has a fresh routing/cache boundary and disabled cache writes; normal turns retain their original session cache key.

## Detection, failure, and degradation

| Mechanism | Positive signal | Failure/degradation signal | Safe response |
|---|---|---|---|
| OpenAI native | `compaction` output item in stream, or successful `response.compaction` object with nonempty canonical `output` and `usage` | Missing item merely means threshold was not crossed; HTTP/API errors are failures. Losing/pruning any standalone output or dropping the encrypted item destroys the next-state contract. `previous_response_not_found` means connection-local continuation state is gone ([WebSocket docs](https://developers.openai.com/api/docs/guides/websocket-mode)). | Preserve untouched full input until compact output validates; on state loss restart from full input or validated standalone compact window. |
| Anthropic native | `compaction` block; `usage.iterations[].type == "compaction"`; optional `stop_reason:"compaction"` when paused | Documented tool interaction can yield `compaction` with `content:null`; unexpected cost is visible only by summing iterations; subsequent request can cache-miss. | Reject null block and keep original history; retry with instructions forbidding tools or fall back to Pi-managed. |
| Pi-managed | `session_compact` success; SDK `compaction_end.result`; persisted entry with usage | Manual errors emit `Compaction failed: …`; auto errors emit `Auto-compaction failed: …` or `Context overflow recovery failed: …`. Only one compact-and-retry overflow recovery is attempted, then Pi advises reducing context or selecting a larger-window model ([source](https://github.com/earendil-works/pi/blob/b4f293684bba718d59cc1157679bcf6157b3a7f5/packages/coding-agent/src/core/agent-session.ts#L1979-L2010), [auto failure](https://github.com/earendil-works/pi/blob/b4f293684bba718d59cc1157679bcf6157b3a7f5/packages/coding-agent/src/core/agent-session.ts#L2196-L2211)). Empty/low-quality summaries have no semantic quality metric. | Extension returns `undefined` to use default; otherwise retain full JSONL, reduce context manually, retry, or switch to larger context. |

## Disposable probe

A local fake Responses SSE server exercised installed `@earendil-works/pi-ai` `0.82.1` without provider calls or cost. Default captured request was:

```json
{"model":"gpt-probe","input":[{"role":"user","content":[{"type":"input_text","text":"hello"}]}],"stream":true,"prompt_cache_key":"session-probe","store":false}
```

`before_provider_request` successfully added `context_management`, proving the request hook. The fake response then emitted a valid `compaction` item followed by text. Both default and injected normalized `AssistantMessage.content` contained only the text block; the compaction item was absent. This confirms source-level finding: request mutation is public, native-state retention is not.

## ADR-ready recommendation

**Decision:** Keep Pi-managed compaction as mandatory baseline for every provider. Do not orchestrate provider-native compaction through `before_provider_request` in production.

**Rationale:** Native compaction offers better preservation of provider reasoning/state, but current Pi adapters neither invoke it nor round-trip its state. Payload hooks can create silent state loss and inaccurate usage. Pi-managed compaction is provider-neutral, observable, persisted, retry-aware, and has a public customization hook.

**Future acceptance gate:** Add native compaction only behind explicit adapter/model capability—not model-name matching—and require: typed request config; typed response block/window; durable session persistence; exact replay rules; full usage accounting; cache metrics; capability probe; null/missing-item rejection; restart/full-context recovery; and automatic fallback to untouched Pi preparation. Until all gates pass, native capability should remain disabled.

**Consequences:** We accept lossy Markdown summaries and a cache-prefix reset today. We avoid a sidecar and avoid pretending provider-native state survives Pi normalization. Re-evaluate on Pi/provider upgrades because both native APIs are evolving (Anthropic beta and rapidly changing OpenAI schemas).
