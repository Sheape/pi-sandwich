# Vite+ output model for a parser-only adapter

Research for the Wayfinder ticket [“Model Vite+ outputs for a parser-only adapter”](https://github.com/Sheape/pi-sandwich/issues/14).

## Decision summary

**Recommend a deliberately small MVP:** an exact-version (`vite-plus@0.2.6`) terminal-text compressor that recognizes only complete, successful shapes, never changes command execution, and otherwise returns the original byte stream and exit status. Do not integrate Vite Task reporter traits or consume its private last-run JSON. Do not rewrite JSON/TAP/JUnit output. Any failure, warning, mixed task result, unmatched filter, incomplete/truncated section, unknown version, unknown reporter, or uncertain stream merge fails open.

This is justified because success output is repetitive enough to save tokens, but Vite+ exposes no unified, public, versioned machine-event protocol for these five commands. Output is composed from Vite+, Oxfmt/Oxlint, Vitest, Vite/Rolldown, and Vite Task, and changes with TTY, stream, CI, color, reporter, cache state, concurrency, and workspace selection.

The installed package declares version `0.2.6`, MIT licensing, and its bundled tool dependencies; the upstream release tag resolves to commit `cd064c68a45fb82badfc1853ff690b1b70511165` ([package manifest](https://github.com/voidzero-dev/vite-plus/blob/v0.2.6/packages/cli/package.json), [release](https://github.com/voidzero-dev/vite-plus/releases/tag/v0.2.6), [license](https://github.com/voidzero-dev/vite-plus/blob/v0.2.6/LICENSE)). Vite+ pins Vite Task to commit `85d4e734c64c96c2ce60e734b3e202b5add53696`, not a Vite+ semver surface ([Vite+ Cargo manifest](https://github.com/voidzero-dev/vite-plus/blob/v0.2.6/Cargo.toml#L308-L312)); Vite Task is also MIT licensed ([license](https://github.com/voidzero-dev/vite-task/blob/85d4e734c64c96c2ce60e734b3e202b5add53696/LICENSE)).

The five commands are wrappers/composites, not one reporter:

- `vp check` captures Oxfmt and Oxlint human output, parses fixed English lines, then prints Vite+ pass/warn/error sections. It forces Oxlint's default reporter because GitHub Actions output omits the expected summary ([implementation](https://github.com/voidzero-dev/vite-plus/blob/v0.2.6/packages/cli/binding/src/check/mod.rs), [parser](https://github.com/voidzero-dev/vite-plus/blob/v0.2.6/packages/cli/binding/src/check/analysis.rs), [guide](https://github.com/voidzero-dev/vite-plus/blob/v0.2.6/docs/guide/check.md)). Formatting failure short-circuits lint.
- `vp lint`, `vp test`, and `vp build` forward trailing arguments to Oxlint, Vitest, and Vite respectively ([CLI types](https://github.com/voidzero-dev/vite-plus/blob/v0.2.6/packages/cli/binding/src/cli/types.rs#L29-L78), [resolver](https://github.com/voidzero-dev/vite-plus/blob/v0.2.6/packages/cli/binding/src/cli/resolver.rs#L77-L225)). Their output contracts therefore belong primarily to bundled upstream versions, not Vite+.
- `vp run` is Vite Task. Its documented modes are interleaved, labeled, and grouped; caching replays captured stdout/stderr; filters may match nothing and still exit zero unless `--fail-if-no-match` is used ([run guide](https://github.com/voidzero-dev/vite-plus/blob/v0.2.6/docs/guide/run.md), [cache guide](https://github.com/voidzero-dev/vite-plus/blob/v0.2.6/docs/guide/cache.md)).

## Instability by channel, TTY, CI, and color

1. **TTY is structural, not cosmetic.** TTY captures began with terminal capability probes and a large gradient `VITE+ - The Unified Toolchain for the Web` banner absent from redirected captures. TTY also changes upstream progress redraws and code-frame styling.
2. **stdout/stderr are semantic.** `check` headings and body can be split; Vitest failure summary and failed-test evidence split; build progress and failure split; task child streams remain distinct. A merged collector may reorder concurrent writes. Parser input must retain `{stream, bytes, sequence}` where available.
3. **CI is not a universal plain mode.** `CI=1` changed byte counts and some rendering but did not create one stable grammar. Vite+ explicitly forces Oxlint's default reporter under GitHub Actions to keep its own human parser working ([source](https://github.com/voidzero-dev/vite-plus/blob/v0.2.6/packages/cli/binding/src/check/mod.rs#L137-L151)).
4. **Color flags do not remove all escapes.** `NO_COLOR=1` left Vite+ styled `check` prefixes in observed redirected output and left Vite progress cursor controls; `FORCE_COLOR=1` expanded SGR usage. Vite Task independently detects color per stream and strips child ANSI when unsupported ([implementation](https://github.com/voidzero-dev/vite-task/blob/85d4e734c64c96c2ce60e734b3e202b5add53696/crates/vite_task/src/session/reporter/mod.rs#L90-L133), [detection](https://github.com/voidzero-dev/vite-task/blob/85d4e734c64c96c2ce60e734b3e202b5add53696/crates/vite_task/src/session/mod.rs#L844-L869)). Strip ANSI only in a shadow view used for recognition; preserve original bytes for fallback/evidence.
5. **Human text is not promised stable.** Vite+'s `check` implementation itself parses upstream English summary lines such as `Finished in`, while Vite Task formats English cache reasons and summary prose in source. These are implementation-tested snapshots, not declared external schemas.

## Parser ownership and fallback model

Adapter input must include command argv, cwd/workspace context if known, exact `vp --version` fingerprint captured independently, exit status, and ordered stream chunks. It must not choose commands, add reporter flags, read caches, or call JS/Rust APIs.

1. **Dispatch:** accept only argv whose executable is `vp`/`vpr` and whose resolved command is exactly one of the five owned forms. Distinguish built-ins (`vp test`) from scripts (`vp run test`).
2. **Version gate:** enable grammar only for exact tested fingerprint `vite-plus 0.2.6` plus bundled component versions above. A bare `0.2.x` range is unsafe. Missing/changed version means byte-for-byte passthrough.
3. **Normalize shadow:** incrementally remove complete ANSI/OSC/control sequences and normalize CR redraws in a shadow buffer. Never alter original evidence buffer.
4. **Mode gate:** recognize pipe versus TTY banner; for `run`, recognize explicit log mode. Unknown terminal control, interactive/watch mode, truncated output, undecodable bytes, or stream-order loss means passthrough.
5. **Parse complete sections:** require opening discriminators, legal transitions, terminal summary, and exit-status agreement. Counts are consistency checks, never authority over process exit.
6. **Safety gate:** if any warning/error/failure/skip/unmatched-filter/cache-error/cancellation marker exists, retain the entire affected section. If boundaries overlap or disagree, retain the entire command output.
7. **Render:** emit concise synthetic summary plus verbatim retained evidence. Keep original exit status. Mark cache replay as replay. Never claim omitted output was executed fresh.
8. **Fail open:** on any parser exception, budget limit, unknown enum/text, or validation mismatch, return original bytes and metadata. No “best effort” partial deletion.

## Safe and forbidden suppression

**Safe only after exact-version, complete-success validation:** TTY branding/terminal probes; repeated progress redraws; timing/thread/start-time noise; successful `check` phase lines reduced to counts; successful Vitest per-file pass rows reduced to final file/test counts; successful build phase chatter and asset rows reduced to final artifact count/size totals; successful `run` cache-hit task blocks reduced to package/task + “cache replay” + saved duration, provided child output contains no warning/error-like evidence.

**Always retain verbatim:** every nonzero command/task result; warnings even with exit 0; code frames, diffs, stacks, file/line/rule IDs, help text attached to diagnostics; stderr from failed or ambiguous tasks; unmatched-filter warnings; cache miss reasons when relevant to mixed/failure runs; cancellation and skipped-task evidence; build size warnings; snapshots/coverage failures; unknown plugin output; JSON/TAP/JUnit; malformed/truncated output. Never suppress based solely on words like `pass`, `✓`, or zero exit. Never pair interleaved task output with the nearest command header.

## ADR-ready recommendation

**Decision:** ship Vite+ adapter in MVP only as an exact-`0.2.6`, parser/compressor-only, success-first terminal adapter.

**Scope:** compress validated successful `vp check`, default `vp test`, successful `vp build`, and all-success/cache-hit `vp run` output; treat default silent `vp lint` success as already optimal. Preserve JSON and all non-success/ambiguous cases. Add golden fixtures for every inventory row, with separate stdout/stderr, merged-order variants, TTY, CI, `NO_COLOR`, `FORCE_COLOR`, each run log mode, cache replay, and unmatched filters.

**Rejected:** Vite Task Rust reporter integration (not a subprocess protocol), private `last-summary.json` consumption (unversioned sidecar), auto-injecting JSON reporters (changes invocation/output), semver-range text parsing, and failure compression.

**Upgrade rule:** every Vite+ or bundled-tool version is unsupported until fixtures are recaptured and grammar explicitly admitted. This keeps adapter useful without letting brittle text scraping hide failures.
